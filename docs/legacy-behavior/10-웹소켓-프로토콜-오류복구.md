# 웹소켓/프로토콜/오류 복구

## 사용자 목적
- 입장 후 게임 세션이 안정적으로 유지되고, 일시적인 네트워크 문제에서 자동 복구되며,
- 복구 실패 시 사용자가 명확한 오류 안내를 받고 안전한 화면으로 돌아간다.

## 진입 위치
- 세션 매니저 초기화 시점.
- `acquire/release/send/subscribe` 호출 시점.
- 소켓 `open/message/error/close` 이벤트 수신 시점.

## 주요 동작 흐름
1. `acquire`로 owner를 등록하면 필요 시 소켓을 생성한다.
2. 연결 URL에 `token`, `roomCode`, `action`, `geId`, `nickname`을 붙여 접속한다.
3. 연결 성공 후 10초 간격 heartbeat(`{"e":1}`)를 전송한다.
4. pong(`e=2`)은 필터링하고 나머지 메시지만 상위로 전달한다.
5. 열리기 전 close는 재연결 스케줄로, 열린 뒤 close는 세션 끊김으로 처리한다.
6. 최대 재시도(3회) 초과 시 연결 실패 오류를 발행하고 메인 화면으로 이동한다.

## 상태 변화
- `currentStatus`: `idle` → `connecting` → `synced` → `reconnecting`.
- owner 집합: 진입/이탈에 따라 증감.
- 재연결 카운터/타이머, heartbeat 타이머 관리.

## 사용 API
- 브라우저 `WebSocket`.
- 브라우저 `history.pushState` + `popstate` 강제 디스패치(실패 시 메인 이동).
- 로컬 저장소 토큰 조회(`localStorage`, `sessionStorage`, URL query).

## 성공 흐름
- owner가 존재하는 동안 연결 유지.
- 쿼리 파라미터가 바뀌면 기존 연결을 정리하고 새 파라미터로 재연결.
- owner가 모두 해제되면 유예 후 소켓 닫기.

## 실패 흐름
- 연결 생성 예외 또는 open 전 close 반복 시 `CONNECTION_FAILED`.
- open 후 close 시 `SESSION_DISCONNECTED`.
- 두 경우 모두 구독자에 오류 이벤트 전달 후 메인 라우트 복귀.

## 로딩 처리
- 별도 UI 로딩은 없고 상태값으로만 표현(`connecting`, `reconnecting`).

## 빈 상태 처리
- owner가 없으면 연결을 만들지 않고 `idle` 유지.

## 검증(Validation)
- nickname/roomCode/action 정규화 후 URL 반영.
- 동일 소켓 중복 연결 방지.
- owner가 남아있으면 release되어도 소켓 유지.

## 상황별 인터랙션/액션 디테일
- 연결 상태는 무음 전환: `connecting -> synced -> reconnecting` 변화는 별도 스피너 없이 내부 상태로만 바뀌므로, 사용자는 화면 유지/오류 모달 발생으로 상태를 체감한다.
- open 전 close 재시도 체감: 소켓이 열리기 전에 끊기면 자동 재시도(백오프)로 이어져, 짧은 네트워크 단절에서는 화면이 유지된 채 복구된다.
- open 후 close 실패 체감: 이미 열린 세션이 닫히면 `SESSION_DISCONNECTED`로 분류되어 메인 이동 + 연결 실패 모달로 전환된다.
- 재연결 한계 초과 체감: 재시도 횟수 초과 시 `CONNECTION_FAILED`가 발생하고, 사용자는 게임 화면을 유지하지 못한 채 입장 화면으로 복귀한다.
- owner 기반 유예 닫기 체감: release 직후 300ms grace를 두어 빠른 라우트 왕복에서 소켓을 즉시 끊지 않으므로 화면 깜빡임과 재접속 지연이 줄어든다.
- join 파라미터 변경 체감: 닉네임/방코드/액션이 달라진 상태에서 acquire되면 소켓을 재구성해 이후 수신 스냅샷이 새 의도와 일치한다.
- pong 필터링 효과: heartbeat pong은 상위 상태에 전달하지 않아 채팅/오버레이 등 사용자 가시 데이터 흐름을 오염시키지 않는다.
- 오류 라우팅 강제 전환: 실패 분류 후에는 `history.pushState` + `popstate` 트리거로 메인 라우트로 즉시 정렬되어, 잘못된 게임 화면 체류를 막는다.

## 부수 효과(Side Effect)
- heartbeat interval 등록/해제.
- reconnect timeout 등록/해제.
- 실패 시 라우트 강제 변경 및 `popstate` 트리거.

## 엣지 케이스
- acquire 시 연결 쿼리가 바뀌었고 소켓이 열려 있으면 즉시 재생성한다.
- release 직후 즉시 닫지 않고 grace 시간(300ms)으로 빠른 재획득을 흡수한다.
- pong 메시지는 수신했더라도 상위 상태를 오염시키지 않는다.

## 관련 엔티티
- `wsSessionManager`
- `connectionStatus`
- join connect params(`roomCode`, `action`)
- 라우트(`main`, `game`)

## 현재 마이그레이션 상태
- 신규 src 존재 여부: 존재 (`openGameSession`, `wsTransport`, `useGameSessionRuntime`).
- behavior parity 충족 여부: 부분 충족.
- 아직 누락된 부분:
  - legacy의 owner 기반 공유 세션과 재연결 정책(최대 3회, 지수 백오프) 축소.
  - legacy의 연결 실패 시점 분류(`opened` 여부 기반)와 복구 단계가 단순화.
- migration 위험 요소:
  - 네트워크 품질이 낮은 환경에서 자동 복구율 저하.
  - 연결 장애가 자주 발생하면 사용자가 반복 재입장을 해야 할 가능성.
