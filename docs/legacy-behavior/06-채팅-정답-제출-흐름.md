# 채팅/정답 제출 흐름

## 사용자 목적
- 참가자가 정답을 채팅으로 제출하고, 턴 진행에 따라 채팅 가시성이 달라진다.
- 최신 메시지 흐름을 놓치지 않도록 자동 스크롤 보조를 제공한다.

## 진입 위치
- 게임 페이지 우측 채팅 패널.
- 모바일에서는 하단 패널 전환으로 채팅 패널 진입.

## 주요 동작 흐름
1. 사용자가 입력창에 메시지를 입력한다.
2. `Enter` 또는 전송 버튼으로 제출한다.
3. 로컬에 내 메시지를 즉시 추가(낙관 반영)한 뒤 서버로 전송한다.
4. 서버 채팅 이벤트 수신 시 발신자 기준 닉네임/내 메시지 여부를 정규화해 추가한다.
5. 사용자가 하단에서 이탈해 있으면 자동 하단 고정 대신 `최신 채팅 이동` 버튼을 노출한다.

## 상태 변화
- 입력 상태: `guessInput`.
- 채팅 목록: `room.chat` 누적.
- 모바일 포커스 상태: `isChatComposerFocused`.
- 자동 스크롤 상태: `chatStickToBottomRef`, `showChatScrollButton`.

## 사용 API
- 웹소켓 이벤트:
  - 클라이언트: `204 GUESS_SUBMIT`
  - 서버: `204/403` 채팅 메시지 이벤트

## 성공 흐름
- 제출 즉시 내 메시지가 목록에 보인다.
- 서버 메시지 수신 시 닉네임/톤/가시성 보정 후 누적된다.
- 새 메시지가 와도 사용자가 과거 메시지를 읽는 중이면 스크롤 위치를 강제로 이동시키지 않는다.

## 실패 흐름
- 공백 메시지는 제출하지 않는다.
- 소켓 전송 실패 시 legacy는 경고 로그만 남기며 로컬 메시지는 남을 수 있다.

## 로딩 처리
- 별도 로딩 인디케이터 없음.
- 입력 가능 조건으로 사실상 진행 상태를 안내한다.

## 빈 상태 처리
- legacy 채팅 목록이 비어 있어도 별도 빈 문구 없음.
- 신규 src는 `아직 메시지가 없습니다.` 문구를 표시한다.

## 검증(Validation)
- legacy 입력 길이: 50자 제한.
- `isComposing` 또는 `keyCode=229` 상태에서는 Enter 제출을 건너뜀.
- 신규 src는 입력 길이 제한은 유지하나 조합 입력 예외 처리 로직이 단순화됨.

## 상황별 인터랙션/액션 디테일
- 채팅 리스트 스크롤 감시: 리스트 하단에서 40px 이상 이탈하면 `chatStickToBottomRef=false`로 바뀌고, 새 메시지 도착 시 자동 하단 고정 대신 버튼 노출 흐름으로 전환된다.
- `최신 채팅 이동` 버튼 노출: `showChatScrollButton=true`일 때만 중앙 하단에 원형 버튼이 떠서 나타나며, 클릭 시 `scrollTo({ behavior: 'smooth' })`로 맨 아래 이동한다.
- 채팅 입력 포커스 강조: 입력 행(`chat-input-row`)은 `:focus-within`에서 테두리 색이 주황 계열로 바뀌고 외곽 glow가 추가된다.
- 모바일 터치 포커스 보정: 입력창 `touchstart`에서 `preventDefault` 후 `focus({ preventScroll: true })`를 직접 호출해 키보드 오픈 시 갑작스러운 브라우저 스크롤 점프를 줄인다.
- 입력 포커스 시 자동 스크롤: `onComposerFocus`에서 채팅 하단 정렬을 호출해, 포커스 직후 최신 메시지가 즉시 보이는 상태를 만든다.
- 채팅 패널 모바일 활성/비활성 전환:
- `game-chat-panel-mobile-active`: 패널 본문(헤더/리스트/입력)이 모두 보이고 카드형 박스가 렌더링된다.
- `game-chat-panel-mobile-inactive`: 헤더/리스트/이동버튼이 숨겨지고 입력 도크만 하단 고정 상태로 남는다.
- 모바일 비활성 패널 포인터 처리: 비활성 패널 자체는 `pointer-events: none`이지만 입력 도크에는 `pointer-events: auto`를 다시 부여해, 패널을 접은 상태에서도 즉시 입력 가능하다.
- 채팅 톤 시각화: `chat-correct`, `chat-alert`, `chat-alert-success`, `chat-sealed`, `chat-highlighted`에 따라 닉네임/본문 색과 강조 굵기가 달라진다.
- 내 닉네임 가독성: 내 메시지 닉네임은 `chat-nickname-mine`으로 굵게 표시된다.
- 입력/전송 버튼 상호작용: 전송 버튼은 입력 공백 시 disabled로 잠기고, hover 시에도 위치 변형 없이 고정(`transform: none`)된다.
- 스크롤바 표시 정책: 채팅 리스트는 thin 스크롤바를 쓰며 hover 시 thumb 명도가 올라간다.

## 부수 효과(Side Effect)
- 모바일 터치 포커스 시 `preventDefault` 후 명시적 포커스 이동.
- 입력 포커스 시 채팅 하단 스크롤 유도.
- 특권 메시지(`privilegedVisible`)는 강조 스타일로 표시.

## 엣지 케이스
- 턴 중 정답자/출제자 간 채팅은 일반 추리자에게 다른 방식으로 보이는 특권 가시성 로직 존재.
- 서버에서 `privilegedVisible`이 누락되면 클라이언트가 턴 정보로 재계산.
- 발신자 세션을 참가자 목록에서 못 찾으면 닉네임을 `알수없음`으로 대체.

## 관련 엔티티
- `room.chat`
- `currentTurn.correctSessionIds`, `currentTurn.drawerSessionId`
- `ChatMessage.privilegedVisible`, `tone`, `mine`

## 현재 마이그레이션 상태
- 신규 src 존재 여부: 존재 (`GameChatPanel`, `useGameChat`).
- behavior parity 충족 여부: 부분 충족.
- 아직 누락된 부분:
  - legacy `privilegedVisible` 강조/가시성 세부 흐름이 신규 채팅 모델/뷰에서 빠져 있음.
  - legacy의 조합 입력 Enter 예외 처리(`isComposing`, `229`)가 신규에서 동일하게 보장되지 않음.
  - legacy의 스크롤-하단 이동 버튼 UX가 신규에서 제거됨.
- migration 위험 요소:
  - 정답자/출제자 전용 채팅 가시성 회귀 시 게임 규칙 체감이 바뀔 위험.

## 2026-05-16 parity 실행 반영
- 검증 완료 범위: 입력 submit, 한글 조합 Enter 예외, 자동 스크롤, 최신 채팅 이동 버튼, 모바일 입력 도크, tone/highlight 표시.
- 수정 내용: 채팅 input을 legacy처럼 항상 사용 가능하게 하고, 공백만 전송 차단한다. `isComposing`/`keyCode=229`에서 Enter submit을 건너뛴다.
- 수정한 UX 흐름: 사용자가 하단에서 이탈한 경우 새 메시지 도착 시 자동 스크롤 대신 floating 버튼을 표시한다.
- 수정한 side effect: 서버 채팅 수신 시 `senderSessionId` 기준 닉네임, `mine`, `privilegedVisible`을 재계산한다.
- 운영 품질 상태: `npm run lint`, `npm run typecheck`, `npm run build` 통과.
- 남은 문제: 서버가 sender echo를 보내는 경우 optimistic 메시지 중복 여부 QA 필요.
