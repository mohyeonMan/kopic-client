# 라우팅/세션 생명주기

## 사용자 목적
- 사용자가 게임 화면으로 들어갈 때 필요한 세션이 자동으로 유지되고,
- 유효하지 않은 진입이나 이탈 시 안전하게 메인 화면으로 복귀한다.

## 진입 위치
- 앱 라우터 초기화 시점.
- 입장 요청 이후 `joinPending`/`joinAccepted` 상태 변화 시점.
- 브라우저 뒤로가기/앞으로가기(popstate) 시점.

## 주요 동작 흐름
1. `joinPending` 또는 `joinAccepted`가 되면 게임 세션 소유권(`owner`)을 획득하고 웹소켓 연결을 유지한다.
2. `joinAccepted`가 되면 연결용 임시 파라미터(`roomCode`, `action`)를 제거한다.
3. 사용자가 `/game`에 있지만 `joinAccepted`가 아니면 `/`로 강제 교체 이동한다.
4. 사용자가 게임 라우트에서 메인 라우트로 이탈하면 `clearRoomCache`를 호출해 방 상태를 초기화한다.
5. 세션 유지 조건이 꺼지면 소유권 해제와 파라미터 정리를 수행한다.

## 상태 변화
- 라우트 상태: `main`/`game` 전환.
- 세션 연결 상태: `idle` → `connecting` → `synced`/`reconnecting`.
- room 캐시: 게임 이탈 시 초기 상태로 정리.

## 사용 API
- 브라우저 히스토리 API: `pushState`, `replaceState`, `popstate`.
- 웹소켓 세션 API:
  - `acquire(owner, nickname, roomCode, action)`
  - `release(owner)`
  - `clearJoinConnectParams()`

## 성공 흐름
- 정상 참여자는 `/game`에서 세션 연결을 유지한 채 게임 진행.
- 메인으로 나가면 세션/방 캐시 정리 후 재진입 준비 상태로 복귀.

## 실패 흐름
- 세션이 없는 `/game` 직접 진입은 즉시 `/`로 리다이렉트.
- 연결 실패 누적 시 메인으로 이동시키고 연결 실패 오류를 발행.
- 연결이 열린 뒤 종료되면 세션 끊김 오류를 발행하고 메인으로 이동.

## 로딩 처리
- 라우팅 레벨 별도 로딩 스피너 없음.
- 연결 상태는 내부 상태(`connecting`, `reconnecting`)로만 유지.

## 빈 상태 처리
- 세션 조건이 없으면 세션 매니저를 유휴(`idle`)로 유지.

## 검증(Validation)
- `shouldKeepGameSession = joinPending || joinAccepted` 조건으로 세션 수명 엄격 제어.
- 현재 라우트가 `game`인지, 직전 라우트가 `game`이었는지 비교해 캐시 정리 시점 제어.

## 상황별 인터랙션/액션 디테일
- 게임 라우트 진입 시 전역 클래스 부여: `app-html-game`, `app-body-game` 클래스를 붙여 게임 화면의 스크롤/오버스크롤 정책을 즉시 전환한다.
- 제스처 억제: 게임 라우트에서 `gesturestart/change/end`, 멀티터치 `touchmove`, 더블탭 `touchend`를 막아 핀치 줌/더블탭 확대로 레이아웃이 흔들리는 것을 차단한다.
- 잘못된 `/game` 진입: `joinAccepted`가 false인 상태에서 `/game`에 있으면 즉시 `/`로 교체 이동되어 화면이 엔트리 레이아웃으로 순간 전환된다.
- 게임 이탈 시 정리 체감: `/game`에서 다른 라우트로 나갈 때 방 캐시를 비우므로, 재진입 시 이전 보드/채팅/참여자 화면이 잔상 없이 초기 상태로 시작된다.
- 모바일 패널 포커스 이동: 하단 탭에서 채팅/참여자 전환 시 대상 패널에 `scrollIntoView(behavior: smooth)`가 호출되고 이어서 `focus({ preventScroll: true })`가 실행된다.
- 채팅 입력 포커스 기반 스크롤: 입력창 포커스 시 페이지 하단 여부를 기준으로 채팅 패널 또는 상태바를 `scrollIntoView`해 모바일 키보드 등장 후도 기준 요소가 시야에 유지된다.
- 모바일 탭 버튼 활성 표현: 활성 탭은 `game-mobile-panel-switcher-button-active`로 배경/텍스트 색이 바뀌고, `focus-visible`에서는 주황색 계열 외곽 링이 추가된다.

## 부수 효과(Side Effect)
- 웹소켓 소유권 획득/해제.
- 메인/게임 라우트 강제 전환.
- 게임 이탈 시 `clearRoomCache` 호출.

## 엣지 케이스
- 닉네임/방코드/액션 파라미터가 바뀐 상태에서 이미 연결 중이면 소켓을 재생성한다.
- release 직후 즉시 닫지 않고 짧은 유예 시간 뒤 닫아 빠른 재진입을 흡수한다.
- 뒤로가기 이벤트 해제 시에도 owner 해제를 보장한다.

## 관련 엔티티
- `session.joinPending`, `session.joinAccepted`
- `room` 캐시 전체
- `connectionStatus`
- `wsSessionManager` owner 집합

## 현재 마이그레이션 상태
- 신규 src 존재 여부: 존재 (`AppRouter`, `useAppRouter`, `GameSessionRuntime`).
- behavior parity 충족 여부: 일부 충족.
- 아직 누락된 부분:
  - legacy의 웹소켓 재연결(최대 3회, 지수 백오프) 정책이 신규에서는 동일 수준으로 보장되지 않음.
  - legacy의 게임 라우트 전역 제스처 억제(핀치/더블탭 줌 방지)는 신규에서 제거됨.
- migration 위험 요소:
  - 네트워크 불안정 환경에서 세션 복구 경험 저하 가능성.
  - 모바일 브라우저에서 의도치 않은 확대/스크롤 제스처로 조작 UX 깨질 위험.
