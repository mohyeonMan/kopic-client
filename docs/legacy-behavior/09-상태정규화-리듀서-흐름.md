# 상태 정규화/리듀서 흐름

## 사용자 목적
- 서버 이벤트 순서가 흔들리거나 payload 키가 달라도, 사용자 화면이 깨지지 않고 일관되게 유지된다.

## 진입 위치
- 웹소켓 수신 이벤트 처리기(`appStateWsAdapter`)에서 리듀서 액션으로 진입.
- 스냅샷 수신(`300`, `408`) 시 정규화 파이프라인 진입.

## 주요 동작 흐름
1. 수신 payload를 이벤트 코드별 디코더로 해석한다.
2. 스냅샷은 legacy 키 변형(`sid/sessionId`, `n/nickname`, `ci/colorIndex` 등)을 흡수한다.
3. room/round/turn/chat/canvas를 표준 shape로 정규화한다.
4. 리듀서가 상태를 단계별로 전이시킨다.
5. 로컬 액션(설정 변경, 정답 제출, 캔버스 clear)은 optimistic 반영 후 서버 동기화를 기다린다.

## 상태 변화
- 세션:
  - `joinPending`/`joinAccepted`/`joinError`/`connectionError`.
- 방:
  - `roomState`(`LOBBY`/`RUNNING`/`RESULT`)
  - `currentRound`, `currentTurn`
  - `participants`, `chat`, `canvas`.
- 연결:
  - `idle`/`connecting`/`synced`/`reconnecting`.

## 사용 API
- 서버 이벤트 코드(대표):
  - 스냅샷: `300`, `408`
  - 참가자: `301`, `302`
  - 게임 흐름: `200`, `202`, `203`, `205`, `206`, `207`, `208`, `209`, `210`, `211`
  - 채팅: `204`, `403`
  - 캔버스: `201`, `402`
- 클라이언트 이벤트 코드(대표):
  - `107`, `200`, `201`, `203`, `204`

## 성공 흐름
- 스냅샷 수신 시 `joinAccepted` 처리와 room 상태 동기화가 동시에 완료된다.
- 턴 전환/정답 처리/결과 반영이 순차적으로 상태에 적용된다.
- 참가자 입퇴장 시 점수판/host/drawerOrder/correctSessionIds 정합성이 유지된다.

## 실패 흐름
- 디코딩 실패 payload는 무시되어 화면 파손을 방지한다.
- join 실패(`1999`) 시 세션/방 상태를 초기화하고 입장 오류를 노출한다.

## 로딩 처리
- 리듀서 레벨 별도 로딩 UI 없음.
- 타이머는 `deadlineAtMs`와 로컬 시각으로 계산.

## 빈 상태 처리
- 정규화 시 누락 필드는 fallback 상태값으로 보정.
- 참가자/채팅/캔버스가 비어도 안전한 기본값 유지.

## 검증(Validation)
- 수치/문자열/배열 타입 검증 후 반영.
- 채팅 특권 가시성 계산:
  - `tone=sealed` 또는 출제자/정답자 조합에서만 강조.
- `serverNowMs`와 `deadlineAtMs`가 있으면 로컬 시각으로 deadline 재보정.

## 상황별 인터랙션/액션 디테일
- 세션 승인과 화면 전환 결합: 스냅샷 정규화에서 `joinAccepted`가 확정되면 라우터 가드가 즉시 통과되어 입장 화면에서 게임 화면으로 전환된다.
- `roomState` 정규화의 UI 파급: `LOBBY/RUNNING/RESULT` 정규화 결과가 설정 카드, 오버레이, 결과 화면 노출 조건을 직접 바꾼다.
- 턴/페이즈 정규화의 UI 파급: `READY/WORD_CHOICE/DRAWING/TURN_END` 값 정합성이 깨지면 오버레이 카드 open/closed 타이밍이 어긋나므로 리듀서가 페이즈 정규화를 강하게 수행한다.
- 정답자 목록 정규화의 UI 파급: `correctSessionIds` 변화는 참여자 카드의 녹색 강조(`participant-card-correct`)와 보드 정답 하이라이트 클래스 활성 조건으로 직결된다.
- 채팅 톤 정규화의 UI 파급: `tone`, `privilegedVisible`, `mine` 정규화 값이 채팅 행 색상/굵기/강조 클래스(`chat-highlighted`)를 결정한다.
- 스냅샷 fallback의 체감 효과: 누락 필드를 기본값으로 채우므로, 네트워크 흔들림에서도 리스트/오버레이가 비정상 빈칸으로 붕괴되는 현상을 줄인다.
- 타임스탬프 보정의 체감 효과: `serverNowMs` 기반 deadline 재보정으로 카운트다운 점프를 완화해, 사용자에게 남은 시간이 급변하는 느낌을 줄인다.
- 캔버스 큐 배치 반영의 체감 효과: inbound stroke를 프레임 단위로 묶어 반영해 연속 드로잉 시 보드 끊김을 줄인다.

## 부수 효과(Side Effect)
- inbound 캔버스 stroke는 `requestAnimationFrame` 큐로 배치 반영.
- 캔버스 clear 이벤트 수신 시 큐 정리 후 상태 clear.
- 일부 이벤트에서 시스템 알림 채팅 생성:
  - 입장/퇴장
  - 방장 변경
  - 정답자 발생

## 엣지 케이스
- 스냅샷에 내 세션 ID가 없으면 닉네임/참가자 목록을 이용해 추론.
- 턴 canvas가 payload에 누락되면 이전 턴 동일 ID 조건에서 기존 stroke 보존.
- 참가자 중도입장(`joinedMidRound`)은 drawerOrder 계산에서 제외.

## 관련 엔티티
- `AppState`, `RoomSnapshot`, `TurnSummary`, `ChatMessage`
- `appStateReducer`, `appStateSnapshot`, `appStatePayloadDecoders`
- `appStateRoom`, `appStateGame`, `appStateChat`, `appStateCanvas`

## 현재 마이그레이션 상태
- 신규 src 존재 여부: 존재 (`gameStore`, `roomSnapshotNormalizer`, `gameSessionApi`).
- behavior parity 충족 여부: 부분 충족.
- 아직 누락된 부분:
  - legacy의 `privilegedVisible` 계산/보존이 신규 chat 모델에서 누락.
  - legacy의 시스템 알림 메시지(입퇴장/방장변경/정답자) 로컬 생성 흐름이 신규에 없음.
  - legacy의 `serverNowMs` 기반 deadline 보정 로직이 신규 정규화에 명시적으로 없음.
- migration 위험 요소:
  - 정규화 보정 감소로 서버 payload 변형 대응력이 떨어질 수 있음.
  - 채팅/타이머/알림 동작의 조용한 기능 축소 위험이 높음.
